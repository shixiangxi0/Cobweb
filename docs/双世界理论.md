# 双世界理论

---

## 两种因果

游戏里存在两种性质根本不同的因果。

第一种是**游戏因果**。血量扣减、获得装备、关卡推进——这些事件改变了游戏的未来，是对世界状态的永久写入。它是离散的，瞬时的，不可逆的，且**绝对串行的**（类似于前端 JS 的单线程事件驱动模型，物理世界的“同时”在这里会被强制排队）。

第二种是**感知因果**。挥刀动画、追击移动、粒子效果——这些状态的演进不影响任何未来的游戏推演，它们服务于当下的体验，结束即消失。与游戏因果的“绝对串行”完全不同，感知因果是**连续的、并行的**。由于它们不持有也不产出因果事实，自然不存在状态写入竞争。因此，场景中可以有无数个动画、音效、粒子系统真正地“同时”并发挥作用。逻辑引擎里同一帧被强制排队的离散事件，在表现层可以优雅地铺展为多轨并行的视觉呈现。

这两种因果运行在不同的轴上（逻辑是离散/串行的，表现是连续/并行的），性质正交。双世界理论的全部，都从这个区分出发。

---

## 三层主权

基于这个区分，系统的因果权力自然分成三层：

```
世界因果树  →  终极因果主权（永久，跨场景）
局部因果层  →  委托主权（随场景生灭）
表现运行时  →  感知主权（可丢弃，不持有因果事实）
```

**世界因果树**是持久层。它只记录需要跨越场景边界的因果事实，不参与局部规则运算，但对下层始终保有最终的抢占权。

**局部因果层**是世界因果树向当前场景颁发的委托主权。场景内的所有状态推演都在这里发生，场景结束时，重要结论写回世界因果树，局部状态整体销毁。

**表现运行时**是渲染组件树。它读取局部因果层的输出，把离散的状态变化呈现为连续体验。它没有持久因果权力，但它并不是被动的——这是理解双世界的关键。

---

## 渲染组件自治

渲染组件不是纯视觉单元，它是**前端组件自治思想在游戏中的延伸**。

一个怪物组件挂载，代表这个怪物存在于世界里。它的 `update(dt)` 里可以跑完整的行为逻辑：检测玩家距离、决策追击、执行攻击前摇。组件卸载，怪物消失。**生命周期本身就是行为的载体。**

组件内的一切——状态、动画、时间相关的行为——默认自治。追击过程中的移动轨迹、攻击动作的帧编排、进入范围的触发检测，这些都在组件内部运行，不需要请示任何上层。

只有当行为**触碰了局部因果层**，才向上报事件：

```
组件内自治（不上报）        触碰局部因果层（上报事件）
──────────────────────     ──────────────────────
追击移动                    命中判定
攻击动画编排                血量扣减
范围检测                    死亡
前摇后摇                    拾取触发
```

这套自治边界让渲染组件成为真正独立的单元——可以组合、嵌套、单独测试，整个组件树的复杂度可以自由拆分，而不影响局部因果层的干净程度。

## 时间因果主权

连续型游戏引出一个更深的问题：ACT 的连击窗口、格挡判定帧、实时物理模拟——这些在一段持续时间内连续地产生状态，它们不是单次事件触发的结果，但它们是真实的因果事实，影响未来推演。它们归属于哪里？

这需要一个新的类似于**Rust里的生命周期**概念来解决——**时间因果主权**。

**时间因果主权是局部因果层在一段时间窗口内对临时状态的完整自治权**。窗口期内，局部因果层可以连续读写临时状态，执行帧级规则，运行物理模拟。格挡判定帧、连击窗口都是局部因果层的内部状态，在时间因果主权的管辖下运行——不应该放进渲染组件。如果把它们放进渲染组件，打断就会引发竞争；因此必须分层管理：打断、撤销等行为，只能是局部因果层的干净状态重置，渲染组件只负责接收新指令，不参与裁决。


时间因果主权有三个核心属性：

- **有时效**：主权存在于一个时间窗口内，窗口关闭，主权自然消亡
- **可撤销**：上层事件到达时，主权可以被立即抢占，局部状态重置
- **沙盒化**：主权窗口只生产结论，不保留过程。过程状态随窗口关闭自然消亡，结论由局部因果层裁决后统一写回。

---

## 确定型结构

世间因果主权中的临时窗口可以被上层随时打断。

比如玩家按下闪避，局部因果先检查当前是否处于可打断状态。若被硬直帧锁定（不可打断），闪避不执行；若可打断，旧时间主权窗口销毁，此时原本的保存的状态有两种选择，一个是提交事务，或者是抛弃事务，然后新窗口建立，同时渲染组件收到新的状态指令。被丢弃的动画帧本来就不是因果事实，什么都不会损坏。

在声明式状态机里，打断是一次强制跳转：

```
animating ──interrupt──> idle
```

表现层状态被强制切换时，渲染组件必须优雅地自治中断——当前动画干净收尾，再切入新状态，不留下视觉残局。这条边显式声明在状态图里，跳转只查它是否存在，判断本身是完全确定性的。

整个系统追求的不是确定性结果，而是确定性结构。闪避有没有成功不确定，但所有可能的结果都被预先枚举，每个出口都有定义好的衔接。不确定的只是走哪条路，不是路本身存不存在。

## 黄金标准

三层结构落地，始终回到同一个问题：

**这件事是否影响未来的因果推演？**

不影响的，归渲染组件，默认自治，可丢弃。影响但只在当前场景内有效的，归局部因果层，随场景生灭。影响跨场景推演的，归世界因果树，必须持久化。
