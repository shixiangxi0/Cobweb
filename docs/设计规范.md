# Cobweb 设计规范

## 核心原则

> 你不是在写"处理玩家输入的代码"，你是在写"这个世界的物理定律"。

---

## 四步设计法

### Step 1：定义状态（State）

**状态是世界的事实。所有状态必须是名词。**

```ts
interface State {
  // 持久状态（跨场景存档）
  persistent: {
    playerLevel: number;
    inventory: Item[];
    completedQuests: string[];
  };

  // 场景状态（随场景销毁）
  scene: {
    player: {
      hp: number;
      mp: number;
      position: { x: number; y: number };
      casting: null | { skillId: string; elapsed: number; duration: number };
      buffs: Buff[];
    };
    enemies: Enemy[];
    turn: number;
  };
}
```

**检查清单：**
- [ ] 每个字段都是名词或名词短语
- [ ] 区分了持久状态和场景状态
- [ ] 临时状态（如 casting）有明确的生命周期字段

---

### Step 2：定义事件（Event）

**事件是改变世界的动作。所有事件必须是动词。**

命名规范：`domain:action[:detail]`

```ts
type Event =
  // 玩家输入
  | { type: 'input:move'; direction: 'up' | 'down' | 'left' | 'right' }
  | { type: 'input:skill'; skillId: string; target?: string }
  | { type: 'input:item'; itemId: string; target?: string }

  // 战斗事件
  | { type: 'combat:attack'; source: string; target: string; damage: number }
  | { type: 'combat:heal'; source: string; target: string; amount: number }
  | { type: 'combat:death'; target: string }

  // 系统事件
  | { type: 'system:tick'; dt: number }
  | { type: 'system:turn:end' }
  | { type: 'system:scene:enter'; sceneId: string }
  | { type: 'system:scene:exit'; sceneId: string };
```

**检查清单：**
- [ ] 事件名是动词或动词短语
- [ ] 使用了 `domain:action` 命名空间
- [ ] 事件负载（payload）只包含必要数据，不包含状态

**反模式：**
```ts
// ❌ 错误：事件里塞状态
{ type: 'combat:attack', targetState: { hp: 100, buffs: [...] } }

// ✅ 正确：事件只包含动作参数
{ type: 'combat:attack', source: 'player', target: 'enemy_a', damage: 20 }
```

### Step 3：写 Reduce（规则推演）

**Reduce 是世界的物理定律。必须是纯函数。**

```ts
function reduce(state: State, event: Event): State {
  // 创建新状态（不可变更新）
  const next = structuredClone(state);

  switch (event.type) {
    case 'input:skill':
      return castSkill(next, event);
    case 'combat:attack':
      return applyDamage(next, event);
    case 'system:tick':
      return advanceTime(next, event.dt);
    default:
      return next;
  }
}
```

**规范：**

1. **纯函数**：不修改外部状态，不调用 API，不生成随机数
2. **原子性**：一个事件要么完全成功，要么完全失败（中间状态不暴露）
3. **单一职责**：一个 reduce 分支只处理一个状态维度
4. **先校验，后修改**：检查前置条件，不满足则直接返回原状态

```ts
function applyDamage(state: State, event: Extract<Event, { type: 'combat:attack' }>): State {
  const target = state.scene.enemies.find(e => e.id === event.target);
  if (!target) return state;  // 目标不存在，无事发生

  // 计算实际伤害（考虑护盾、减伤等）
  const actualDamage = calculateDamage(event.damage, target.buffs);

  // 应用伤害
  target.hp -= actualDamage;

  // 检查死亡
  if (target.hp <= 0) {
    target.hp = 0;
    // 死亡作为派生事件，由系统在下一次 dispatch 时处理
    state.scene.pendingEvents = state.scene.pendingEvents || [];
    state.scene.pendingEvents.push({ type: 'combat:death', target: target.id });
  }

  return state;
}
```

**检查清单：**
- [ ] reduce 是纯函数（相同输入永远产生相同输出）
- [ ] 不直接修改原状态（使用克隆或不可变更新）
- [ ] 每个分支有明确的前置条件检查
- [ ] 副作用（如 emit 新事件）通过返回值或 pendingEvents 延迟处理

### Step 4：表现层映射（Presentation Mapping）

**表现层只读快照，不做逻辑判断。**

```ts
const renderer = {
  lastSnapshot: null as State | null,

  update(snapshot: State) {
    const last = this.lastSnapshot;
    const curr = snapshot;

    // 检测状态变化，触发视觉效果
    this.detectChanges(last, curr);

    this.lastSnapshot = structuredClone(curr);
  },

  detectChanges(prev: State | null, curr: State) {
    // HP 变化 → 血条动画
    if (prev?.scene.player.hp !== curr.scene.player.hp) {
      this.playHPFloatingText(curr.scene.player.hp - prev!.scene.player.hp);
    }

    // 新 Buff → Buff 图标
    const newBuffs = curr.scene.player.buffs.filter(
      b => !prev?.scene.player.buffs.find(pb => pb.id === b.id)
    );
    newBuffs.forEach(b => this.playBuffAcquireEffect(b));

    // 死亡 → 死亡动画
    const diedEnemies = curr.scene.enemies.filter(
      e => e.hp === 0 && prev?.scene.enemies.find(pe => pe.id === e.id && pe.hp > 0)
    );
    diedEnemies.forEach(e => this.playDeathAnimation(e));
  },
};
```

**检查清单：**
- [ ] 表现层不调用 reduce，不修改状态
- [ ] 表现层通过快照 diff 检测变化
- [ ] 视觉效果不依赖事件时序，只依赖状态变化

## 常见设计模式

### 模式 1：临时状态（可打断行为）

```ts
// 状态
casting: null | { skillId: string; elapsed: number; duration: number }

// 开始施法
reduce({ type: 'input:skill', skillId }) {
  state.casting = { skillId, elapsed: 0, duration: 2000 };
}

// 时间推进
reduce({ type: 'system:tick', dt }) {
  if (state.casting) {
    state.casting.elapsed += dt;
    if (state.casting.elapsed >= state.casting.duration) {
      // 施法完成，结算效果
      resolveSkill(state.casting.skillId);
      state.casting = null;
    }
  }
}

// 打断
reduce({ type: 'input:dodge' }) {
  if (state.casting) {
    state.casting = null;  // 直接清空，无效果
  }
}
```

### 模式 2：Buff / Debuff

```ts
// 状态
buffs: Array<{ id: string; type: string; duration: number; stacks: number }>

// 添加 Buff
reduce({ type: 'buff:apply', buff }) {
  const existing = state.buffs.find(b => b.type === buff.type);
  if (existing) {
    existing.stacks++;
    existing.duration = Math.max(existing.duration, buff.duration);
  } else {
    state.buffs.push({ ...buff, stacks: 1 });
  }
}

// 时间推进时衰减
reduce({ type: 'system:tick', dt }) {
  state.buffs = state.buffs
    .map(b => ({ ...b, duration: b.duration - dt }))
    .filter(b => b.duration > 0);
}
```

### 模式 3：派生事件（事件链）

```ts
// 攻击导致死亡，死亡导致掉落
reduce(state, event) {
  const pending: Event[] = [];

  switch (event.type) {
    case 'combat:attack':
      applyDamage(state, event);
      if (isDead(state, event.target)) {
        pending.push({ type: 'combat:death', target: event.target });
      }
      break;

    case 'combat:death':
      removeEnemy(state, event.target);
      const drops = calculateDrops(event.target);
      drops.forEach(item => {
        pending.push({ type: 'loot:drop', item, position: getPosition(event.target) });
      });
      break;
  }

  return { state, pending };
}

// 事件总线处理派生事件
function dispatch(event: Event) {
  const { state, pending } = reduce(currentState, event);
  currentState = state;
  pending?.forEach(dispatch);  // 递归处理派生事件
}
```

## 检查清单（Checklist）

### 设计阶段
- [ ] 所有状态字段都是名词
- [ ] 所有事件名都是动词
- [ ] 每个事件都有对应的 reduce 分支
- [ ] 状态分层清晰（持久 / 场景 / 临时）

### 实现阶段
- [ ] reduce 是纯函数
- [ ] 不直接修改原状态
- [ ] 表现层只读快照
- [ ] 每个 reduce 分支有单元测试

### 验证阶段
- [ ] 事件序列可以回放
- [ ] 状态变化可以追溯
- [ ] 极端输入（边界值）有处理
- [ ] 打断/撤销行为正确清理状态

---

## 一句话总结

> **先设计状态（Model）和事件（Action），再写 reduce 规则（Store Mutation），最后映射表现（View Rendering）。决定游戏未来走向的核心逻辑流，在写 reduce 的那一刻就完全确定了。**
